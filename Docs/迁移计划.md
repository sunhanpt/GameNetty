# CapybaraGo-Unity 的 GameNetty 重写目标

源项目为 `D:\REA\CapybaraGo-Unity`。交付目标是通过 GameNetty 登录进入原有营地与旅程，由 Unity 负责交互和表现，由 .NET Gate 执行玩法、生成战报和持久化账号进度。

## 运行与验证

1. 构建 `Server/Server.sln`，启动本机 MongoDB，然后运行 `Start Server(Single Process).bat`。如果本机已有同端口的旧版 GameNetty，测试时需要启动本次构建的版本。
2. 用 Unity 2022.3.62f3 打开 `Unity`，进入 `Assets/Scenes/main.unity`。本机联调可在 `ET → 连接本地服务器 (127.0.0.1)` 选择目标。输入同一账号可继续旅程。
3. 运行 `dotnet run --project Tools/CapybaraSmoke` 验证 Gate 所用规则引擎、MemoryPack 战报、BSON 快照和指令重试。附加 `-- --catalog` 可逐关验收开局、首步推进和存档恢复，覆盖全部章节和单人挑战。
4. 运行 `Publish-linux-x64.ps1` 生成带 SHA-256 清单的服务端包。发布包包含 `CapybaraRules.dll` 和两端共用的玩法配置。

### 联机验收

在运行新版 GameNetty 的本机测试环境执行下列命令。联机用例创建随机测试账号并写入该服务端的 MongoDB。指定独立测试数据库即可保留这些测试记录供复查。

```powershell
$smoke = Join-Path $PWD 'Logs/CapybaraSmoke'
dotnet msbuild Tools/CapybaraSmoke/CapybaraSmoke.csproj -restore -m:1 "-p:OutDir=$smoke/"
if ($LASTEXITCODE -ne 0) { throw 'CapybaraSmoke build failed' }
dotnet (Join-Path $smoke 'CapybaraSmoke.dll') --server 'http://127.0.0.1:30300/'
```

用例从 `/get_router` 发现 Realm，再经过 Realm 和 Gate 登录。它向同一 Gate 会话连续发送两条使用相同版本号的开局、转盘领取、战斗回合和返回营地指令，检查一次生效、版本冲突、相同请求重试和参数变更冲突。重登后比对转盘奖格、保存版本与结算快照，并读取同账号的《风灯旅记》独立进度。
